画面のデザインは作らない。計算結果を確かめるための簡単な確認ページだけを作る。

## 3. モデル

### 3.1 運動方程式（1 区画）

```
Paw(t) = V(t) / C + R × V'(t) + PEEPi_base − Pmus(t)
```

ここで V は機能的残気量からの容量の増分。吸気と呼気で抵抗を分けられるようにする（Rinsp、Rexp）。COPD の流量制限を表すため。

- 時間刻み dt = 0.005 秒（`// model:` 波形の滑らかさと計算量の折り合い）
- 積分は 4 次の Runge–Kutta を基本とする。圧規定の呼吸では Paw が決まっていて V' を求め、量規定の呼吸では V' が決まっていて Paw を求める
- 呼気は受動的で、呼気弁の圧は設定 PEEP（APRV では Plow）。V' = −(V/C + PEEP − Paw_valve … ) のように、肺胞圧と回路圧の差を Rexp で割って求める

### 3.2 自発呼吸 Pmus

- 1 呼吸を「吸気努力の山（半正弦波）＋休止」で表す。パラメータは振幅 Pmus_max（cmH2O）、自発呼吸回数、吸気努力の時間（`// model:`）
- 振幅 0 は深い鎮静・筋弛緩の状態
- トリガはフロートリガとし、患者側へ向かう流量が設定値（L/min）を超えたら補助呼吸を始める。トリガの遅れは 1 ステップでよい

### 3.3 換気モードの動作

| 共通 ID | 吸気の始まり | 吸気中の制御 | 吸気の終わり |
|---|---|---|---|
| VC-AC | 時間、または患者トリガ | 流量一定（矩形波）。漸減波は選べるようにする | 設定 VT を送り終えたら流量 0 にし、設定 Ti まで吸気ポーズ |
| PC-AC | 時間、または患者トリガ | Paw = PEEP + ΔP。立ち上がり時間を設定できる | 設定 Ti（時間） |
| PRVC | 時間、または患者トリガ | PC-AC と同じ。ΔP を呼吸ごとに調整して目標 VT に近づける | 設定 Ti |
| PSV／CPAP | 患者トリガのみ | Paw = PEEP + PS。立ち上がり時間を設定できる | 吸気流量がピークの ETS（%）まで下がったとき。CPAP は PS = 0 |
| APRV／BIPAP | 時間（Thigh／Tlow） | 高圧 Phigh と低圧 Plow を交互に保つ。どちらの圧でも自発呼吸ができる | 時間 |

PRVC の ΔP の調整幅は取扱説明書に数値がない。初期値として「1 呼吸あたり最大 ±3 cmH2O、測定 VT と目標 VT の比で比例的に調整」を `// model:` として置き、報告に含める（伊藤先生の確認待ちの項目にする）。最初の 1 呼吸（試験呼吸）の扱いも同様に `// model:` とする。

### 3.4 機種ごとの圧の上限ルール

`src/config/ventLayouts.js` の DEVICE_RULES を読み、機種 ID（'pb980'、'hamilton'、'evita'）を引数で受け取って適用する。数値をエンジン内に直接書かない。

| 機種 | 適用するルール |
|---|---|
| pb980 | VC+（PRVC）の目標吸気圧は PEEP + 3 を下回らない。BiLevel の PH は PL + 5 以上 |
| hamilton | 供給圧はリミット圧で頭打ち（超える設定ではフラグを立てる）。アラーム上限 = リミット圧 + 10。APVcmv（PRVC）の吸気圧はリミット圧を超えない、最小吸気圧（ピーク圧 − PEEP）は 5 |
| evita | 最大気道内圧はアラーム上限 − 5 に制限（autoset 無効の既定） |

頭打ちになった呼吸には `pressureLimited: true` を付け、Phase 2 のアラーム表示で使えるようにする。

### 3.5 吸気ホールド・呼気ホールド

- 吸気ホールド：吸気の終わりで吸気弁と呼気弁を閉じ、流量 0 のまま一定時間保つ。そのときの Paw をプラトー圧 Pplat とする
- 呼気ホールド：呼気の終わりで両弁を閉じ、流量 0 のまま一定時間保つ。そのときの Paw を total PEEP とし、auto-PEEP = total PEEP − 設定 PEEP
- 1 区画モデルでは保持中に圧は変化しないが、保持時間は設定できるようにしておく（Phase 4 の多区画で振り子換気を入れる余地）

### 3.6 1 呼吸ごとの実測値

PIP、Pplat（吸気ポーズまたは吸気ホールドがある呼吸のみ）、Pmean、設定 PEEP、total PEEP（呼気ホールド時）、VTi、VTe、RR（強制・自発）、MVe、Ti、Te、I:E、Cstat = VT ÷（Pplat − total PEEP）、Raw =（PIP − Pplat）÷ 吸気終末の流量（流量一定の VC のときのみ）、ドライビングプレッシャー ΔP = Pplat − total PEEP。

## 4. テスト（受け入れ条件）

理論値と照合できる条件でテストする。許容誤差は ±2 %（auto-PEEP は ±5 %）。

| No. | 条件 | 期待値（理論） |
|---|---|---|
| 1 | VC-AC、流量一定 1 L/s（60 L/min）、VT 0.5 L、Ti 1.0 s、R 10、C 0.05 L/cmH2O、PEEP 5、Pmus 0 | PIP = 0.5/0.05 + 10×1 + 5 = 25 cmH2O、Pplat = 15、Cstat = 50 mL/cmH2O、Raw = 10 |
| 2 | PC-AC、ΔP 15、Ti 1.0 s、立ち上がり 0、R 10、C 0.05（τ = 0.5 s）、PEEP 5、Pmus 0 | VTi = 0.05 × 15 ×（1 − e^−2）= 0.6485 L |
| 3 | 2 と同じ肺で呼気を十分長く（Te ≥ 5τ） | 呼気の容量が V(t) = V0 × e^(−t/τ) に従う（3 点で照合） |
| 4 | VC-AC、VT 0.5 L、RR 30、Ti 1.0 s（Te 1.0 s）、C 0.06、Rexp 20（τ = 1.2 s）、PEEP 0、20 呼吸後 | 呼気終末の残り容量 = 0.5 × k/(1 − k)、k = e^(−1/1.2) → 0.384 L、auto-PEEP = 0.384/0.06 = 6.41 cmH2O。呼気ホールドの total PEEP − 設定 PEEP と一致 |
| 5 | PSV、PS 10、ETS 25 %、Pmus あり | 吸気の終わりの流量がピーク流量の 25 % ± 1 ステップ分 |
| 6 | PRVC、目標 VT 0.5 L、C 0.05、R 10 | 数呼吸で VT が目標 ±5 % に収まる。収まるまでの呼吸数を報告する |
| 7 | PRVC、hamilton、リミット圧を低く設定 | 吸気圧がリミット圧を超えず、目標 VT に届かず、pressureLimited が立つ |
| 8 | PRVC、pb980、肺が非常に柔らかい（C を大きく） | 目標吸気圧が PEEP + 3 を下回らない |
| 9 | APRV、Phigh 25、Plow 5、Thigh 4.0 s、Tlow 0.6 s、Pmus 0 | 圧が 2 レベルを時間どおりに切り替える |
| 10 | 同じ入力で 2 回計算 | 出力が完全に一致する |
| 11 | ventLayouts.test.js（既存） | 引き続き通る |

テスト 4 の期待値の導き方（定常状態で、呼気終末の残り容量 Vee は「(Vee + VT) × k = Vee」を満たす）をテストのコメントに書く。

## 5. 確認用ページ（EngineViewer）

伊藤先生が公開ページで計算の正しさを確かめるための画面。機種の見た目は作らない。

- 患者の肺（C、Rinsp、Rexp）と Pmus をスライダーで変える
- モードと設定値を選ぶ。機種 ID（pb980、hamilton、evita）も選べ、圧の上限ルールの違いが確かめられる
- 圧・流量・容量の 3 波形を、時間軸をそろえて Canvas で描く（10 秒分のスクロール表示）
- 1 呼吸ごとの実測値を表で示す
- 吸気ホールド・呼気ホールドのボタン
- 画面上部に「開発確認用。機種の画面は Phase 2 以降」と表示する

App.jsx から切り替えて表示できるようにする（URL の `#engine` で開く）。
