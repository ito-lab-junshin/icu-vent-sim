# Phase 2 指示書：人工呼吸器の画面（PB980 風）と設定操作（Claude Code 用）

作成：2026-11-11　対象リポジトリ：icu-vent-sim　前提：DESIGN.md v0.7、CLAUDE.md、Phase 1 完了（main）

この Phase では、Phase 1 の計算エンジンを「PB980 風」の人工呼吸器の画面につなぐ。
学習者が設定を変えると、波形と実測値が変わるところまでを作る。
血液ガスや SpO2 はまだ変わらない（Phase 3）。Hamilton 風と Evita 風の画面は作らない（Phase 5）。

2026-11-11、伊藤先生の「始めてください」を受けて、8 の表の「案」のとおりに進めた（8 の決定事項を参照）。

## 0. 作業の前に必ず守ること

1. 着手前に DESIGN.md、CLAUDE.md、docs/REFERENCES.md、docs/PHASE1.md、src/config/ventLayouts.js、src/engine の各ファイルを読む。
2. 疑義が出たら実装を止めて質問する（CLAUDE.md の 1）。とくに次の場合は必ず止まる。
   - この指示書と DESIGN.md の内容が食い違うとき
   - PB980 の設定範囲・初期値・アラームの動作など、機種の仕様を新しく使う必要があり、docs/REFERENCES.md に登録されていないとき
   - 画面の値とエンジンの値が合わず、原因が画面側かエンジン側か判断できないとき
3. 機種の仕様値を新しく使うときは、docs/REFERENCES.md と src/config/references.js に出典と status を登録する（CLAUDE.md の 2）。原文で確認できていない値は `unverified` とし、画面に「参考値（未確認）」と表示する。
4. ガイドライン値（肺保護換気の目標値など）は、この Phase でも使わない。
5. 実在機器のロゴ、アイコンの絵柄、商標デザインは写さない。画面構成（配置、波形の並び、操作の流れ）だけを参考にする。
6. 教育用モデルとして自分で決めた係数は、コード内に `// model: ...` と理由を書き、最後の報告で一覧にする。
7. 作業は `phase2-pb980` ブランチで行う。main に入れると公開ページが更新されるので、伊藤先生の了承があるまで main には入れない。
8. 終わったら `npm test` と `npm run build` が通ることを確認し、報告して止まる（Phase 3 に進まない）。

## 3. 作る内容

### 3.1 画面の構成（DESIGN.md 5.1 の PB980 風）

| 領域 | 内容 |
|---|---|
| 上部バナー | 患者データ 8 項目：Ppeak、Pmean、PEEP、I:E、ftot、VTE、VE TOT、O2。左右の送りで追加の項目（Pplat、Cstat、Rstat、total PEEP、auto-PEEP、VTI）を表示 |
| 中央 | 波形 3 段（Pcirc、V̇、VT）。配置を切り替えて、波形＋ループ（P-V、F-V）も表示できる |
| 下部 | 左下にモード表示（例：A/C VC）と PBW。中央に主要設定。右にアイコン（自作の絵柄） |
| キー | 吸気ポーズ、呼気ポーズ、用手換気、アラーム消音、アラームリセット、回転ノブ |

- O2 の実測値は、設定値をそのまま表示する（ガス交換は Phase 3）。
- 上部バナーの値は、エンジンの 1 呼吸ごとの実測値（breathMetrics.js）から取る。画面側で計算し直さない。
- Pplat、Cstat、Rstat は吸気ポーズをした呼吸の値、total PEEP と auto-PEEP は呼気ポーズをした呼吸の値を、次に測るまで表示し続ける。測っていないときは「—」。
- App.jsx の「人工呼吸器」の区画に、この画面を表示する。Hamilton C6 風と Evita V800 風のボタンを選んだときは「Phase 5 で作成」と表示する。
- 確認用ページ（`#engine`）は残す。

### 3.2 設定の流れ

DESIGN.md 5.1 の順にする。

```
性別と身長 → PBW（src/engine/patient.js）
  → Mode（A/C、SIMV、SPONT、BiLevel）
  → 強制換気の種類（PC、VC、VC+）または自発換気の種類（PS）
  → トリガー（フロートリガ V̇sens）
  → 主要設定
  → 確定
```

| PB980 風の選択 | 共通 ID（エンジン） |
|---|---|
| A/C ＋ VC | VC-AC |
| A/C ＋ PC | PC-AC |
| A/C ＋ VC+ | PRVC |
| SPONT ＋ PS | PSV（PS 0 で CPAP） |
| BiLevel | APRV（TH と TL の設定で APRV にも BIPAP にもなる） |
| SIMV | エンジンにない。選べない表示にし、「未対応」と示す |

表示名は `src/config/ventLayouts.js` の MODE_NAMES から取る。画面に直接書かない。

### 3.3 設定の保留と確定

- 設定に触ると、その値は「保留」になる（色を変えて示す）。ノブ（画面上のノブ、上下の矢印キー、マウスホイール）で値を変える。
- 「確定」を押すまで、エンジンには渡さない。「取り消し」で元の値に戻る。
- 複数の設定をまとめて変え、1 回の確定で反映できる。
- モードの切り替えは、確定のあと、次の呼気中に反映される（エンジンの既存の動作）。
- 設定の範囲・刻み・初期値は `src/config/ventLayouts.js` に持ち、画面に直接書かない（値は 8 の A で決める）。

### 3.4 PB980 の設定値とエンジンの設定の対応（settingsMap.js）

| PB980 風の設定 | エンジンの settings | 換算 |
|---|---|---|
| f | rr | そのまま |
| VT（mL） | vt（L） | ÷ 1000 |
| V̇max（L/min） | flow（L/s） | ÷ 60 |
| 流量波形（矩形波、Ramp） | flowPattern | 'square'、'ramp' |
| TPL（プラトー時間） | ti | 矩形波：ti = VT ÷ V̇max + TPL。Ramp：ti = 2 × VT ÷ V̇max + TPL（エンジンの漸減波のモデルに合わせる） |
| PI（PEEP 上の吸気圧） | deltaP | そのまま |
| TI | ti | そのまま（PC、VC+） |
| VT（VC+ の目標） | targetVt | ÷ 1000 |
| PSUPP | ps | そのまま |
| ESENS（%） | etsPct | そのまま |
| V̇sens（L/min） | triggerFlow（L/s） | ÷ 60 |
| PEEP | peep | そのまま |
| PH、PL、TH、TL | pHigh、pLow、tHigh、tLow | そのまま |
| 立ち上がり（%） | riseTime（s） | 8 の B で決める |
| PEAK アラーム上限 | pPeakAlarm | そのまま |
| O2 | （エンジンに渡さない） | 表示のみ |

### 3.5 エンジンへの追加

Phase 1 から持ち越した項目と、画面のキーに必要な項目だけを足す。

1. **PEAK アラーム上限での吸気の打ち切り（pb980）**：吸気中に気道内圧が PEAK アラーム上限に達したら、その吸気をすぐに終えて呼気に移る。その呼吸に `highPressureTerminated: true` を付ける。2026-11-11 に「Phase 2 でアラームと一緒に入れる」と決定した項目。数値は DEVICE_RULES から読み、VC+ の目標吸気圧の上限（PEAK アラーム上限 − 3）とぶつからないことをテストで確かめる。
2. **用手換気**：呼気中にキーを押すと、いまの設定で強制換気を 1 回送る。maneuvers.js に予約の関数を足す（吸気ホールドと同じ形）。吸気中に押したときは何もしない。
3. **アラームの判定（alarms.js）**：設定された上限・下限と実測値を受け取り、鳴っているアラームの一覧を返す純粋関数。対象は 8 の D で決める。

漸減波の終末流量、立ち上がりの波形は、8 の B と C の答えに合わせて直す。答えがなければ Phase 1 のまま（`// model:`）とする。

### 3.6 アラームの表示

- 鳴っているアラームを上部に表示する。優先度の色分けは、資料で確認できた範囲で行う。
- アラーム消音とアラームリセットのキーを置く。消音の時間、リセットの動作は 8 の D で決める。
- 音は出さない（講義室で使うため。出すかどうかは後の Phase で相談）。
- Phase 1 の `pressureLimited`（VC+ の目標吸気圧が上限に達した）も、ここで表示する。

### 3.7 確認用の患者パネル

シナリオは Phase 4 で作るので、この Phase では確認用のパネルで肺を変える。

- コンプライアンス、吸気抵抗、呼気抵抗、Pmus（振幅、回数、吸気努力の時間）をスライダーで変える。
- 画面の端に折りたたんで置き、「確認用（シナリオは Phase 4）」と表示する。
- 初期値は確認用ページと同じ（C 50 mL/cmH2O、Rinsp 10、Rexp 10、Pmus 0）。機種の既定値でもシナリオの値でもない。

### 3.8 画面の大きさと表示

- 講義室の PC（幅 1280 px 以上）で、人工呼吸器の画面全体がスクロールなしで見えるようにする。
- 幅が狭い端末では、横にはみ出さず、縦に並べ替える（スマートフォンへの対応の程度は DESIGN.md 8 の 7 で未決定）。
- 画面の文字は日本語。設定名・実測値名は PB980 の表記（英語の記号）を使う。数値と単位の間は半角スペース。
- キーボードだけで設定を変えられるようにする（タブで移動、上下の矢印で値を変える、Enter で確定）。

## 4. テスト（受け入れ条件）

画面の見た目はテストしない。計算と状態の動きを、純粋関数のテストで確かめる。

| No. | 条件 | 期待値 |
|---|---|---|
| 1 | settingsMap：A/C VC、f 12、VT 500 mL、V̇max 60 L/min、TPL 0.5 s、矩形波、PEEP 5 | エンジンの設定が rr 12、vt 0.5、flow 1、ti 1.0、flowPattern 'square'、peep 5 |
| 2 | 1 と同じで Ramp | ti = 2 × 0.5 ÷ 1 + 0.5 = 1.5 |
| 3 | 1 の設定を画面からエンジンに渡して 1 呼吸 | Ppeak 25、Pplat 15（Phase 1 の受け入れ条件 1 と同じ値） |
| 4 | PBW：男性 170 cm、女性 160 cm | 66.0 kg、52.4 kg |
| 5 | 設定を変えて確定しない | エンジンに渡る設定は変わらない。取り消しで元の値に戻る |
| 6 | 2 つの設定を変えて 1 回確定 | 2 つとも同時に反映される |
| 7 | 範囲の外の値を入れる | 範囲の端で止まる |
| 8 | PEAK アラーム上限での打ち切り：VC-AC、流量 1 L/s、VT 0.6 L、R 10、C 0.02、PEEP 5、PEAK アラーム上限 30、pb980 | 気道内圧が 30 に達した時点（入った量 0.3 L：5 + 0.3 ÷ 0.02 + 10 × 1 = 30）で吸気が終わる。VTi = 0.3 L ± 2 %、`highPressureTerminated` が立つ |
| 9 | 8 と同じ肺で VC+（PRVC） | 目標吸気圧は 27（PEAK アラーム上限 − 3）を超えず、打ち切りは起きない |
| 10 | 用手換気：呼気中に予約 | 次のステップで強制換気が 1 回始まる。吸気中の予約では何も起きない |
| 11 | アラームの判定 | 条件を満たす間だけ一覧に入る（対象は 8 の D で決めたもの） |
| 12 | 上部バナーの値 | エンジンの実測値と同じ（単位の換算と丸めだけ）。VE TOT = 直近 1 分の分時換気量 |
| 13 | 同じ入力で 2 回計算 | 出力が完全に一致する（追加した機能を含めて） |
| 14 | Phase 1 のテスト（53 件） | 引き続き通る |

許容誤差は Phase 1 と同じ（±2 %）。

## 5. ブラウザでの確認

テストのほかに、実際のブラウザで次を確かめ、報告に結果を書く。

1. 初期状態で波形が流れ、上部バナーに値が出る。
2. VT を変えて確定すると、次の呼吸から波形と VTE が変わる。確定前は変わらない。
3. A/C VC → A/C PC → A/C VC+ → SPONT PS → BiLevel の順に切り替えて、どれも波形が出る（SPONT は Pmus を上げる）。
4. 吸気ポーズで Pplat、Cstat、Rstat が出る。呼気ポーズで total PEEP、auto-PEEP が出る。
5. 呼気抵抗を上げて呼吸回数を増やすと、呼気の流量が 0 に戻らなくなり、呼気ポーズで auto-PEEP が出る。
6. PEAK アラーム上限を下げると、アラームが表示され、吸気が打ち切られる。
7. 幅 1280 px でスクロールなしに画面全体が見える。幅 390 px で横にはみ出さない。
8. ブラウザのコンソールにエラーが出ない。
