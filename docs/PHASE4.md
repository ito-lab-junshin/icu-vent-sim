# Phase 4 指示書：肺のモデル・シナリオ・血液ガス・画像・肺損傷（Claude Code 用）

作成：2026-11-13（案）　対象リポジトリ：icu-vent-sim　前提：DESIGN.md v0.7、CLAUDE.md、Phase 3 完了（main）

この Phase では、「適切な設定では改善し、不適切な設定では改善しない、または悪化する」経過を作る。
そのために、肺そのものが設定に応じて変わるようにし（PEEP で開く、下げると虚脱する、過膨張する、損傷がたまる）、
3 つの病態シナリオ、血液ガスのオーダー、胸部 X 線・CT の模式図、鎮静や腹臥位などの処置を足す。

内容が多いので、**4A と 4B の 2 段階に分ける**。4A が終わったら報告して止まり、伊藤先生の確認のあとで 4B に進む。

| 段階 | 内容 | 終わりの目安 |
|---|---|---|
| 4A | 3 区画の肺（リクルート・虚脱・過膨張）、シナリオ 3 つ、血液ガスのオーダー | PEEP を上げると酸素化が良くなり、下げると時間をかけて悪くなる。シナリオを選んで始められる |
| 4B | 肺損傷の蓄積と回復、病態の経過、処置（鎮静・筋弛緩・腹臥位など）、呼吸ドライブ、腎臓の代償、X 線・CT の模式図 | 数時間の経過で、設定によって改善・悪化が分かれる。検査でそれを確かめられる |

**この指示書は案である。「8. 着手前に伊藤先生が決めること」に答えが入るまで、実装を始めない。**

## 0. 作業の前に必ず守ること

1. 着手前に DESIGN.md、CLAUDE.md、docs/REFERENCES.md、docs/PHASE1.md〜PHASE3.md、src/engine、src/ui を読む。
2. 疑義が出たら実装を止めて質問する（CLAUDE.md の 1）。とくに次の場合は必ず止まる。
   - この指示書と DESIGN.md の内容が食い違うとき
   - シナリオの患者の値、肺損傷の係数など、この指示書の 8 で決めていない値を新しく決める必要があるとき
   - ガイドラインの値（プラトー圧の上限、一回換気量の目標、PEEP／FiO2 の表など）を使わないと実装できないとき
3. **ガイドライン値は、この Phase でも計算に使わない。**肺損傷は「圧や換気量が大きいほど、なだらかに増える」モデルで表し、ガイドラインの上限値を境目として使わない。画面にも「適切」「不適切」の判定を出さない（ヒントと振り返りは Phase 7）。
4. 生理学の式を新しく使うときは、Phase 3 と同じく出典を docs/REFERENCES.md と src/config/references.js に登録する（status: `model`）。
5. 教育用モデルとして決めた係数は、コード内に `// model: ...` と理由を書き、報告で一覧にする。**肺のモデルと肺損傷の係数は、値を決める前に、代表的な条件での経過を表とグラフで報告し、伊藤先生に見てもらう。**
6. 胸部 X 線・CT は模式図を自作する。実際の画像、教科書の図、機器の画面は写さない。
7. 作業は `phase4a-lung`、`phase4b-injury` ブランチで行う。main に入れると公開ページが更新されるので、伊藤先生の了承があるまで main には入れない。
8. 各段階が終わったら `npm test` と `npm run build` が通ることを確認し、報告して止まる。

## 3. モデル

### 3.1 3 区画の肺（4A）

肺を 3 つの区画の割合で表す（合計 1）。

| 区画 | 意味 | 換気 | 血流 |
|---|---|---|---|
| 正常区画 | 含気がある肺 | される | ある |
| リクルート可能区画 | 虚脱しているが開く肺。開いている割合 o（0〜1）を持つ | 開いている分だけされる | ある |
| 非リクルート区画 | 浸潤・硬化した肺 | されない | ある（シャント） |

```
含気している割合 = 正常区画 + リクルート可能区画 × o
コンプライアンス C = 肺全体が含気したときの C × 含気している割合 × 過膨張による低下
シャント率 =（非リクルート区画 + リクルート可能区画 ×（1 − o））× 血流の配分の係数
```

- 呼吸メカニクスの計算は Phase 1 の 1 区画の式のまま使い、C を 1 呼吸ごとに更新する（8 の B）。
- 過膨張：吸気終末の肺胞圧が高いほど、C がなだらかに下がり、肺胞死腔率が上がる。関数の形と係数は `// model:`。
- 血流の配分の係数：虚脱した肺への血流が減る効果（低酸素性肺血管収縮）を 1 つの係数で表す（`// model:`）。

### 3.2 リクルートと虚脱（4A）

- **開く**：吸気終末の肺胞圧が開放圧を超えると、o が上がる。目標値は圧に対するなだらかな曲線（シグモイド）で、速く進む（秒〜分の時定数）。
- **閉じる**：呼気終末の圧（total PEEP）が閉鎖圧を下回ると、o が下がる。目標値は別のシグモイドで、ゆっくり進む（数十分〜数時間の時定数）。
- 開放圧は閉鎖圧より高い。そのため「いちど開いた肺は、開いたときより低い PEEP でも開いたままでいられる」（ヒステリシス）が再現される。
- o は遅い状態として持ち、1 呼吸ごとに進める。時間経過ボタンでも進める。
- 開放圧、閉鎖圧、曲線の幅、時定数はシナリオごとの値とし、`// model:` とする。

### 3.3 シナリオ（4A）

| シナリオ | 主な学習目標（DESIGN.md 6） | Phase 4 での範囲 |
|---|---|---|
| 正常肺（術後など） | モードごとの波形の違い、設定と実測値の関係、ホールドの意味 | 肺は変化しにくい。設定の練習用 |
| 重症 ARDS | 肺保護換気、PEEP の決め方、腹臥位、検査の読み | 人工呼吸器と処置で管理する。VV ECMO は Phase 6 |
| COPD 増悪 | auto-PEEP の発見と測定、呼気時間の確保、外部 PEEP、過度な換気による悪化 | 気管支拡張薬で呼気抵抗が下がる |

- シナリオは「患者の値」「最初の人工呼吸器設定」「病態の経過（4B）」を持つ。値は 8 の D の表の案を、伊藤先生が確認してから使う。
- シナリオを選ぶと、最初から始まる（経過時間 0、トレンドは空）。途中で選び直すと、確認のあとでやり直す。
- 学習者の画面から、確認用の患者パネルを外す。確認用ページ（`#engine`）には残し、シナリオの値を読み込めるようにする。

### 3.4 血液ガス（4A）

| 項目 | 求め方 |
|---|---|
| pH、PaCO2、PaO2、SaO2、HCO3 | Phase 3 の計算 |
| P/F 比 | PaO2 ÷ FiO2 |
| BE | 式は 8 の F で決める |
| Lac | 8 の G で決める |

- 「血液ガス」をオーダーすると、その時刻の値が結果として出る。結果は採血時刻つきで履歴に残り、前回との差が分かるようにする。
- 結果が出るまでの待ち時間は 8 の H で決める。
- 学習者の画面で PaO2・PaCO2・pH が見られるのは、この結果だけとする（モニタには出さない）。

### 3.5 肺損傷の蓄積と回復（4B）

肺損傷指数（0 以上）を遅い状態として持ち、時間で積分する。

増える要因（DESIGN.md 4.5）：

- プラトー圧・ドライビングプレッシャーが高い状態の持続
- メカニカルパワーが高い状態の持続
- 虚脱と再開放のくり返し（1 呼吸ごとに開いたり閉じたりする量）
- 高い FiO2 の持続
- 強い自発努力による大きな一回換気量

肺への反映：損傷がたまると、数時間かけて「正常区画が減り、非リクルート区画が増える」「肺全体のコンプライアンスが下がる」。
回復：損傷を増やす要因が小さい状態が続くと、ゆっくり減る。

- どの要因も、値が大きいほどなだらかに増える関数で表す。**ガイドラインの上限値を境目に使わない。**
- メカニカルパワーの式を使う場合は、出典を登録する（8 の I）。
- 係数を決める前に、8 の J の代表的な条件での経過を報告し、伊藤先生に見てもらう。

### 3.6 病態の経過（4B）

シナリオごとに、肺損傷とは別の「病気そのものの経過」を持つ（例：ARDS は数日かけて非リクルート区画がゆっくり減る、COPD は気管支拡張薬のあと呼気抵抗が下がる）。
時間の関数として定義し、`// model:` とする。

### 3.7 処置（4B）

| 処置 | 効果 |
|---|---|
| 鎮静の調整（浅い・中等度・深い） | 呼吸ドライブ（Pmus の大きさ）が変わる |
| 筋弛緩 | Pmus が 0 になる。効果が切れる時間を持つ |
| 腹臥位／仰臥位 | リクルート可能区画が開きやすくなり、血流の配分が変わる。効果は時間をかけて出る |
| 気管支拡張薬 | 呼気抵抗・吸気抵抗が下がる（COPD）。効果が切れる時間を持つ |
| 吸引 | 分泌物による抵抗の上昇を戻す。分泌物は時間とともにたまる |

効果の大きさと時間は `// model:` とする。薬の名前と用量は出さない（8 の K）。

### 3.8 呼吸ドライブ（4B）

Pmus の大きさと自発呼吸回数を、PaCO2（または pH）、SpO2、鎮静の深さから決める。
PaCO2 が上がる・pH が下がる・SpO2 が下がると大きくなり、鎮静が深いと小さくなる。筋弛緩中は 0。
強い自発努力では、PSV や APRV で一回換気量が大きくなり、3.5 の肺損傷が増える。

### 3.9 腎臓による代償（4B）

PaCO2 が高い状態が続くと HCO3 が数時間〜数日かけて上がり、低い状態が続くと下がる。時定数と上がる量は `// model:`。
COPD シナリオは、最初から HCO3 が高い状態（慢性の代償）で始める。

### 3.10 胸部 X 線・CT の模式図（4B）

| 検査 | 模式図 | 状態との対応 |
|---|---|---|
| 胸部 X 線（正面） | 胸郭、左右の肺野、心臓の影、横隔膜、気管チューブ | 浸潤影の範囲と濃さ = 非リクルート区画と、虚脱しているリクルート可能区画。過膨張では肺野が暗く、横隔膜が下がる（COPD、高い PEEP） |
| 胸部 CT（横断像 1 枚） | 胸郭の断面、左右の肺、心臓、脊椎 | 背側（腹臥位では腹側）に濃い浸潤、その腹側にすりガラス状の領域、含気している領域。PEEP と腹臥位で分布が変わる |

- SVG で描く。imaging.js が「領域ごとの白さ」を数値で返し、画面はそれを描くだけにする。
- オーダーした時刻の状態を描き、履歴に残す。前回の画像と並べて見られるようにする。
- 結果が出るまでの待ち時間は 8 の H で決める。
- 画像の下に「模式図です。実際の画像ではありません」と表示する。

### 3.11 時間制御との関係

- o、肺損傷指数、HCO3、処置の残り時間、病態の経過は、どれも遅い状態として持つ。
- 時間経過ボタンは、これらを 1 分刻みで進める。途中で C やシャント率が変わるので、一定の間隔（`// model:`、例：10 分ごと）で呼吸メカニクスを測り直す。
- 12 時間の時間経過が、数秒以内に終わるようにする。

## 5. ブラウザでの確認

### 4A

1. シナリオを選ぶと、その患者と設定で始まる。選び直すと、確認のあとでやり直す。
2. ARDS シナリオで PEEP を上げると、SpO2 が上がる。下げて「1 時間進める」と、SpO2 が下がる。
3. COPD シナリオで、呼気の流量が 0 に戻らない波形が出る。呼気ポーズで auto-PEEP が出る。

5. 学習者の画面に、確認用の患者パネルが出ない。確認用ページには出る。
6. 幅 1280 px でスクロールなしに全体が見える。幅 390 px で横にはみ出さない。コンソールにエラーが出ない。

### 4B

7. 筋弛緩で自発呼吸が消え、時間がたつと戻る。
